# 브랜치 규칙

## 이름 규칙

```
feature/<Git 아이디>_<작업내용>
```

- Git 아이디: 소문자. 누가 하는 작업인지 바로 보이게
- 작업내용: 어떤 작업을 하는지 구체적으로

## 브랜치 단위

> 기능 하나 커밋 하나 / 기능 3개 브랜치 하나
> 
- 브랜치 하나가 하루 안에 끝나는 크기가 적당합니다.
- 오래 살아 있는 브랜치는 `main` 과 멀어져서 나중에 충돌이 크게 납니다. (끝난 브랜치는 삭제)
- 작업이 커질 것 같으면 쪼갤 수 있는지 먼저 생각합니다. 예를 들어 "몬스터"를 한 브랜치로 잡지 말고 "패트롤", "시야 감지", "추적" 으로 나눕니다.

## 만들고 지우기

**만들 때**는 반드시 최신 `main` 에서 생성

1. `main` 으로 이동
2. `Pull origin`
3. `Branch > New Branch`

**지울 때**는 PR이 병합된 직후

1. GitHub의 PR 화면에서 `Delete branch` (원격)
2. GitHub Desktop에서 `Branch > Delete` (로컬)
